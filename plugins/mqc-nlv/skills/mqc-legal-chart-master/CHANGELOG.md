## 0.11.0 · 2026-10-27 · 随套件 v2.5.0 · 新增画法：点阵阶梯、法条沿革、区间胶囊、双读饼；发射扇照样图重画

起因：作者给了几张编辑型样图，问能不能放进图库，「改成我们的风格，有些图要做得优雅一点」。作者从中挑定这四种。
**只借图形，不借配色**：仍是风格原色（灰阶 + 唯一重音），不透明、不渐变。样图里斜放的类目名一律改横排
（V6 与 PPTX 导出都不出斜字）；横排两行放不下、又全是汉字的，竖排（一字一行，字仍是正的）。
原来能出图的说明，出图结果一个字节不变（成品账原有 210 份指纹逐一核过，只新增 56 份）。

**新画法（图种从十三种到十七种）：**
- `cascade` 点阵阶梯：几个类目各有多少件，一格 = `per` 件（不写由脚本选 1、2、5、10……里最小的一档），
  一列方块由少到多排成阶梯，列顶印数值。格数四舍五入时副标题写明；一列最多 30 格，不到半格的一项会被拒。
  `order: "given"` 按给出的先后、底边齐平。方块与百点方阵同一种模块（奇川风圆角、歸藏风直角）。
- `lineage` 法条沿革：一行一部法律（司法解释、合同、章程），横向是年份；实心点 = 通过，空心圈 = 修改，竖线 = 废止，
  现行有效的线画到截至年份。右栏印状态与修改次数（次数由脚本数）。年份标签放得下就上下交替标出，有一处放不下就全图不标。
  `marks` 可换叫法（合同沿革写「签订 / 变更 / 终止」）。n 等于行数。
- `interval` 区间胶囊：每一项一段从低到高的区间，竖着画成胶囊，上端印 to、下端印 from；可选白点 `mid`（中位数、点估计，
  要写 `mid_label`）。可为负，纵轴含 0。场景库原有的「区间」画法由待建改为可画；四条其实不是区间的场景改挂横条或哑铃。
- `radpie` 双读饼：角度 = 占比，从内圈量起的长度 = `size`（平均审理天数、平均标的）；要写 `size_label`。
  占比不足 1.5%、或 size 不到最大值二十分之一的扇区会被拒（窄到、短到看不见）。value 是件数时 n 等于各扇区之和。

**守卫（每一条都在 break_tests 里确认能失败，新增 9 条）：**
- G5：点阵阶梯每列格数 = 数值 ÷ per 四舍五入、格一样大、等距叠放；法条沿革每个标记与生命线两端都在同一把年份尺上；
  区间胶囊上下沿与白点按像素核在同一把纵轴尺上（贴着 0 的数按比值核会被坐标舍入误拦）；
  双读饼的长度 ∝ size，角度由回读的面积反算、与占比核对。
- G6：区间胶囊必须有 0 线；双读饼各扇区同心、从同一个内圈量起。G9：点阵阶梯的格必须是方块模块。
- 标题核数：点阵阶梯认件数与占 n 的比例；法条沿革认修改次数、施行年数、通过到最后一次修改的年数，年份须在材料里
  （修改次数不做两两相减，否则「民法典修改 6 次」会借「公司法比民法典多 6 次」混过去）；区间胶囊认端点、宽度、倍数与中位数；
  双读饼认占比、size 与两两之差。

**发射扇照作者给的样图重画（10-27 作者两次给图后定稿）：**
- 根在左下角，辐条默认由长到短、从近乎竖直一根根顺时针倒下来，最后一根略低于水平线；
  每根辐条一个圆（面积 ∝ size；没写 size 就是同样大小的起点圆），从圆往外一格一个小点，点数 = 数值；
  圆沿一道螺旋往外排、互不相压；标签顺着辐条写在点的尽头，后面跟着数值；灰度随先后一档档变浅，重音只有一处。
- 新增可选的 `start`（都写，并写 `start_label`）：圆就在 start 处，径向是同一把尺，虚线弧标刻度
  （例如立案后第几周首次开庭、开庭后又审了几周），按 start 排。没写 start 时圆的远近只为排开，弧不标数。
- 顺着辐条写的字是 V6 第一次出转过的字：SVG 写 `rotate`，V1 的 PPTX 导出器照样转写（文本框带 rot，位置换算到框中心），
  守卫按转过之后的字框核出界与互压。
- 排不开（辐条太多、标签太长、圆小到看不见）时自动改用 0.10.0 的外弧排法；随机 1,920 组对照，原来画得出的一组不少，另多 6 组。
  常见数据里约八成用样图的排法。
- 玫瑰：10-27 曾改成由大到小加圆心小孔，作者看过后要求退回原来的画法，已原样退回（成品与 0.10.0 一字节不差）。
- 成品账只有发射扇示例的 14 份变化，其余一个字节不变。

**其余：** schema、图种目录、SKILL.md 写法表、README（新样图 `assets/gallery-0.11.png`）补齐；场景库新增 12 个场景、3 种画法（430 个场景、68 种画法）；
新增示例 4 份（十九份）；判定账新增 16 条；回归新增「十四」一节。法条沿革示例的年份按公布的法律文本整理（以官方文本为准）。
随机造的 3,840 份说明（四种图 × 两种风格 × 四种画布）里，没有一份崩溃、没有一份出图后守卫不过——要么出图，要么说清为什么不画。


## 0.10.0 · 2026-10-26 · 随套件 v2.5.0 · 新增画法：气泡矩阵、发射扇、放射汇聚（另有备用的漏斗）

起因：作者给了一页编辑型信息图（「产品八年，一页年鉴」：发射扇、放射汇聚、气泡年鉴、漏斗），问 V6 能不能画。
**只借图形，不借配色**（作者定的）：颜色仍是风格原色（灰阶 + 唯一重音），不透明、不渐变，ADR 0010 不动。
原来能出图的说明，出图结果一个字节不变（成品账 154 份原有指纹逐一核过，只新增、不改动）。

**新画法（图种从九种到十三种）：** 作者 10-27 定：漏斗的形状不够好看，保留但不主推，作备用画法；主推气泡矩阵、发射扇、放射汇聚。
- `funnel` 漏斗：一级比一级少，条宽 ∝ 件数、各级共用一条中线；右侧印出占第一级的比例。有增有减会被拒，指向逐级加减。
- `matrix` 气泡矩阵（年鉴）：行 × 列，气泡面积 ∝ 数值，自带行合计与列合计；没写的格就是 0；
  `status: "dashed"` 画虚线圈（试行期、当年数据不全），必须写 `dashed_label` 说明含义。
  奇川风的气泡是「手作」的卵石形：形状由格的 id 哈希决定（同一份说明永远同一个形状），**面积缩放到恰好等于同半径的圆**；歸藏风用正圆。
  emphasis 可以指向一行或一列。
- `fan` 发射扇：从一个根发出几根辐条，辐条长 ∝ 数值，辐条上一个小点一格；可选 `size`，外圈圆面积 ∝ size。
  圆与标签排在最外圈之外的同一道弧上（短辐条的端点挤在根部，贴着端点放会互相压住），标签挤时自动外退一档，还挤就拒。
- `converge` 放射汇聚：一圈条目各自汇入所属主题，枢纽面积 ∝ 条目数；条目名要么都写要么都不写，放不下就拒，不缩字号硬塞。
  n 必须等于条目数；emphasis 只能指向一个主题。

**守卫：**
- G5 新增面积核对（气泡、外圈圆、枢纽：圆按 πr²、卵石形按回读的轮廓面积），容差 1.2% 加坐标舍入量，小气泡不被误拦；
  漏斗条宽、发射扇辐条长按长度核。G6 新增：漏斗各级共用中线、发射扇辐条同根。
- 漏斗的收窄带按「流」处理，两种风格下都是直角（与桑基、汇入图的流带同一条规矩）。
- 标题核数：漏斗认各级与第一级、上一级之比；气泡矩阵认格值、行列合计与占比，同一行或同一列里只认相邻、与第一个、与最后一个相比
  （全部两两相比会让编的数也对得上）。

**其余：**
- 回归的对比度检查：压在气泡上的数字按气泡的颜色核，不按纸色（标在 `data-bg` 上）。
- schema、图种目录、硬规则、SKILL.md 的写法表补齐四种；场景库登记两种新画法（`fan`、`converge`），`matrix`、`funnel` 改为可画，新增 8 个场景。
- 新增示例 4 份（十五份示例）；README 加一张新图种的样图（`assets/gallery-0.10.png`）。
- 跨 Python 版本：V1 共享内核的 PPTX 导出器原用 `sum()` 量文字宽度（3.12 起浮点补偿求和），放射汇聚示例的一个文字框
  在 3.11 与 3.12+ 上差 1 EMU；改为逐字累加后 3.9 / 3.11 / 3.12 / 3.13 四个版本逐字节一致，原有成品在四个版本上都不变。
- V7 法律课件大师「换一种图」会自动多出这四种：数据形状对得上的（例如一组逐级减少的件数可换成漏斗）就能换，对不上的 V6 会说为什么。


## 0.9.8 · 2026-10-13 · 随套件 v2.4.0 · 数是脚本数的，每个数追得回原件

学 Perspective、diagram-design、VGraph、graphify、案图之后的一轮升级。先拍基线，新检查逐条在旧代码上确认会失败；
原来能出图的说明，出图结果除下面写明的两处外一个字节不变（逐件比对过 942 种写法）。

**修（发版闸门，首次在 GitHub 上跑时撞到）：** 可选依赖（jsonschema、openpyxl）没装时那一项打 SKIP，原来闸门只认 OK / FAIL，
作者本机装着 jsonschema、把这一项记进了名单，GitHub 上没装就被判「检查不见了」「项数变少」。现在跳过的照名字算在、项数也算一项。
另：GitHub 上闸门不过时，把不过的那几行标到检查结果上，不必翻整份日志。

**新：数据集 + 视图（学自 Perspective）。**
- 手上是一件一行的记录时，模型不再自己数：把记录照录进 `dataset`，在 `view` 里写按哪一列分组、计数还是求和、
  筛哪些、怎么排、留前几类，脚本算成 data。竖柱、横条、百点方阵、玫瑰、逐件分布、桑基、汇入图都支持。
- 逐格溯源：图上每一项来自哪几行、对应哪个编号，出图时写进 `<名>.trace.json`，交付清单里点明。
- n 可以不写，由脚本逐行数出；缺字段的行不悄悄丢，交付清单点名行号。
- 给了 dataset 又手改 data：两边对不上就拒。V7 按模块清单重画时会重算核对，与原图逐字节一致。
- 新增示例 `examples/dataset-causes.json`（十一份示例）。

**修：**

  现在都说人话、点名字段。`"unit": null` 原来让百点方阵崩溃，现在当作没写。

**第二轮自检（同日，发版前）又查出并修掉的：**

**第三轮自检（同日）：**

  两项全插件检查改为并行，回归耗时回到一分半。

**第四轮自检（同日，按 Windows 律师的真实环境测）：**
- **记事本另存的「UTF-8 带 BOM」**（记事本、PowerShell 5、Excel「CSV UTF-8」都这样存）：V1–V6 原来一律报「JSON 写坏了，第 1 行第 1 列」。
  全插件读文件改为兼容 BOM（不带 BOM 的文件解码逐字节不变；写文件仍不带 BOM），七个模块实测：带 BOM 与不带出图逐字节相同。
- **记事本存的 GBK 判决书**：V4、V5 原来按 UTF-8 读、忽略错误，悄悄读成乱码（「ԭ׹˾뱻ҹ˾…」）还当作已读；V2 直接报错。
  现在 UTF-8 读不通就按 GBK 读，且读出来的汉字六成以上是常用字才认（真判决书实测为 100%）；Big5 繁体等认不准的，停下请用户另存为 UTF-8。
- **Excel 默认另存的 GBK 案例清单**：类案编码原来甩 UnicodeDecodeError，现在按 GBK 读入并提示。
- **只 `pip install openpyxl`、没有 lxml 的电脑**：V4 原来拒绝交付（自检 X3 / X6 不过），根因是 openpyxl 没有 lxml 时把空值写成 `<v />`，
  公式缓存一步只认 `<v></v>`，序号列没有缓存值——手机与网盘预览里序号是空的。两种写法都认了。
- 类案编码 `cases.py`、`module.py fit`：坏输入原来甩堆栈；路径打错时还误报成「探测出 0 页，文件可能损坏」。现在说人话、说「找不到」。
- 声明的最低版本是 Python 3.9：用真的 3.9 跑过 V3、V4、V6、V7 全套，CI 的多版本任务加上 3.9。
- 另核过、没有问题的：10 万行登记表出图不到 1 秒；11 个示例的 PPTX 用演示软件打开与 SVG 逐张一致；交付包里没有杂物，脱敏守卫全过。

  （插件更新时会被整个替换）、没有真的看过图片就不说「看过了」。先实测了七个模块从别的目录调用都正常，产物都落在当前目录。

  关系图大师打印 `python scripts/ask.py …`，只在技能目录里能跑。现在在哪个目录照抄都能跑。
