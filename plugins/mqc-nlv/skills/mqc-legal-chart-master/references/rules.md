# 硬规则

每一条都有守卫或校验在执行；守卫的编号见 `scripts/guards.py`。

## 一、数字

1. **图上的数只许算、不许编。** JSON 里只有原始数值；合计、占比、中位数、增长率、超过阈值的
   件数全部由 `spec.py` 计算。标题与批注里的每个阿拉伯数字都要落在算出来的集合里（四舍五入到整数
   或一位小数都算对；「超过 30 件」这类带界词的允许向下取整）。数字紧贴汉字（「增长9876%」）与
   带空格的写法一样被抽出、一样被核——0.8.0 在这里有漏洞（外部测试 T020 / T028），0.9.0 修好。
   全角数字照常识别；分组写错的（「12,34」）直接拒。
1b. **数要分类型，主语要对得上。**（0.9.0）
   - 带 % 的只能是占比、增长率；写「个百分点」的只能是两个百分比之差；其余是件数、金额、差额、倍数。
     「从 40% 提高到 60%」是「提高 20 个百分点」或「增长 50%」，写「提高 20%」会被拦下；
   - 数字所在分句里有类目名时，核它是不是**这个类目**的数：驳回 26 件、全额支持 41 件，
     「驳回率 41%」会被拦下，提示 41% 属于「全额支持」；
   - 冒号不断句：「驳回：41%」的主语就是驳回（0.9.1）；
   - 「A 比 B 多 / 少 / 高 / 低 X」：大小对、方向反了也拒（0.9.1）；
   - 否定说法（「未获支持」「不予支持」）不是图上的类目名，指哪几类说不清，要求直接写类目名（0.9.1）；
   - 几个类目合起来的件数或占比（「全额支持与部分支持合计 74%」「74% 的诉请获支持」），只有分句里点到了
     **恰好这几个类目**才认；合计安到单个类目上（「全额支持占 74%」）拒（0.9.1）；
   - 年份要能在口径、来源或类目里找到（时间范围写进 scope）；条文编号（第 577 条）、案号不是数据，
     不核，列进请核；「第 N 件」是顺序编号，N 不能超过样本量（0.9.1）。
   - 中文逗号分组（「1，234」）与科学计数法（「1e6」）写法有歧义，直接拒（0.9.1）。
   - 这仍是**数字层**的核对，不是语义证明：「胜诉率」「超审限」「因某证据败诉」这类概念与因果，
     数字对上了也要人判断。
2. **中文约数按区间核。**（0.9.0 起，原来不核）「四成」= 35%–45%，「三分之一」= 30%–36%，
   「过半」> 50%（恰好 50% 不是过半，0.9.1），「并未过半」「不足四成」按否定方向核；有主语时只拿
   这个类目的占比核，类目之间的比值不能替它作证；「翻倍」、「两倍」按倍数 ±5%。图上没有一个数落在区间里就拒（外部测试 T014：
   41% 写成「九成」）；对上了仍列进请核，约数的分寸由人定。区间放得宽，宁可放过边缘说法，不误拦正常写法。
3. **n 必填，能对账的一律对账。** 百点方阵（件数模式）、玫瑰、逐件分布、哑铃、桑基的 n 由数据
   反算，与说明不符就拒；竖柱与横条的数值不一定是件数，n 照录。
4. **百点方阵要写明件数还是百分比**（`measure`）。合计恰好 100 的件数与百分比长得一样，
   靠猜会把写错的 n 悄悄放过。

## 二、几何

5. **纵轴从 0 起，不断轴。**（G6）柱的契约是长度 ∝ 数值，断轴毁契约。极端值就让它冲天。
6. **角的风格跟着风格走。**（G9）
   - 奇川风：柱、节点、玫瑰扇区，凡是矩形、三角形、多边形的角，一律是三次贝塞尔小圆角
     （整页幻灯片上 5px，随画布缩放，不小于 3px；边太短时自动收小），线头是圆头，箭头除外。
     PPTX 里矩形还原成原生圆角矩形，其余形状细分成折线保留圆角。
   - 歸藏风：一律直角、平头。瑞士风格要的是利落，出现圆角即拦下。
   - 细长条例外（两种风格都适用）：桑基与汇入图两侧的竖条、逐件分布的中位数竖线，边不磨圆、
     线头平头，颜色用深灰（奇川风 #4B5563、歸藏风 #737373），不用近黑。磨圆了即拦下。
   - **流带也是长条**（0.9.3，作者定的）：桑基与汇入图的流带，两种风格下四个角都是直角，
     与两侧的竖条统一。磨圆了即拦下（G9）。
   - **点阵用方块模块，不用圆点**（作者定的）：百点方阵的每一格、图例色块，都是正方形。奇川风圆角 =
     边长 × 0.22（比大形状的角圆一些，但一眼看去仍是正方形；守卫允许 15%–30%，太尖不像模块、
     太圆就成了圆点），歸藏风直角。方块也是 V7 课件磁吸模块的视觉语言，两边用同一条规则。
     逐件分布与哑铃的点是落在数轴上的位置，不是点阵，仍用圆点。
7. **面积编码开平方。**（G5）玫瑰图的半径 ∝ √数值。
8. **几何只由一把比例尺决定。**（G5）守卫从产物回读每根柱、每个点、每条带，比值不一致就拒。

## 三、视觉

9. **一图一处重音。**（G2）重音色只给 `emphasis` 指向的那一个数据（及其标签、流向它的带）。
10. **色板白名单。**（G1）两种风格各有白名单，取自 V1 已冻结的规范；数据图多出来的「灰阶梯」
    也在白名单内。
11. **字不小于 11px，不出界、不互压。**（G3、G4）
11b. **平面。**（G10）不透明、不渐变、不加阴影。唯一的例外是汇入图的流带：半透明是为了让交叉处
   叠深，读者看得出几股流在那里重叠——透明度本身在表达数据，不是装饰。PPTX 里同样保留透明度。
12. **图名照录。**（G8）图上的图名与 `title` 一字不差。

## 四、颜色只用风格原色（0.9.3）

奇川风：灰阶 + 唯一深红 #991B1B；歸藏风：灰阶 + 克莱因蓝 #002FA7。**不接受自选强调色，也没有颜色预设。**
说明 JSON 里写 `accent`、命令行给 `--accent` 都会被拒，并说明原因；要换气质就换风格。

为什么取消：0.7.0 曾开放九个强调色预设（含墨绿、石青、绛紫）与任意色值，外部测试一跑，图上就出现了绿、青、紫，
与奇川风、歸藏风都不是一回事（作者定的，ADR 0010）。

律所要所有图都一个样子，就写一份**档案**（`profiles/example-firm.json` 是样板）：风格、画布、字体存在
`~/.mqc-nlv/profiles/<律所名>.json`，出图时 `--profile <律所名>`。优先次序：命令行 > 说明 JSON > 档案 > 默认。
0.9.2 以前的档案里若写了强调色，不用、照常出图，交付清单里说一声。

## 四之一、批注（G11）

一句旁白 + 一条虚线贝塞尔引线 + 一个落点，放在右侧批注栏，不压在数据上。

- 一页**最多两条**。第三条起读者就分不清哪条要紧；其余的话放讲稿或下一页。
- 只支持竖柱、横条、哑铃、逐级加减：这几种图上「一个数据」有明确的位置。
- 批注是作者的话，不要求照录；但里面的**阿拉伯数字与标题同一条规矩**：只许算、不许编。
- 引线的路线由脚本搜出：不压任何文字、不穿过别的数据形状、两条引线不挨着。搜不到就明说，
  请用户换一个目标或把话写进标题——不硬画。

## 四之三、复杂度预算

每种图一页能放的对象有上限（`spec.BUDGET`）：竖柱 14、横条 16、百点方阵 4 类、玫瑰 12、哑铃 12、
逐件分布 6 组、桑基 14 个节点、汇入图两侧合计 16、逐级加减 12 级。超了不挤，**拆成「总览 + 细节」
两页**，或合并长尾为「其他」。用到七成以上，出图计划里提醒「接近上限」。

## 四之四、动笔前先确认

用户的要求不止一种画法、或要上公众号与小红书时，先跑 `make.py 说明.json --plan`，把出图计划
（图种、画布、风格、重音、批注、预算、请核项、守卫结果）原样给用户看，确认后再出图。

## 四之二、不出白描

数据图的去处是课件与屏幕，不打印、不进卷宗（作者定的）。要求白描时明说不支持。

开放整套色板会把三种风格的统一打散，所以不开放。

## 六、灵动画法的诚实规则

V6 的灵动画法（单位图标阵、天平、冰山、拼图、旅程、倒计时、金句卡、气泡、蒲公英……）可以活泼，
但每一种都有一条不能破的线：

| 画法 | 那条线 |
| --- | --- |
| 单位图标阵 | 一个图标代表多少人或多少件，必须写在图上；不足一个单位的不凑整 |
| 天平 | 倾角只由两边的数量差算出，不由「我觉得哪边更有理」决定 |
| 冰山 | 水上水下的比例按金额或件数算；不可量化的项只列不画比例 |
| 要件拼图 | 拼块来自法条或司法解释列明的要件，不自己拆 |
| 旅程图、倒计时 | 每段时长、每个期限都要有来源或由规则计算 |
| 金句卡、问答摘录、文书高亮、条文批注 | 原文照录，注明案号、页码或条文号；只许删、不许改 |
| 气泡群、蒲公英 | 面积编码开平方；茎长、气泡大小与数值成正比 |
| 四象限、雷达、光谱（慎用） | 坐标与评分必须有可数依据，写在图上；没有依据不出图 |

## 五、什么时候说不

| 要求 | 回应 |
| --- | --- |
| 断轴柱状图 | 拒绝；让极端值冲天，或拆一张放大图 |
| 3D、阴影、渐变、发光 | 拒绝；平面是三种风格共同的底线 |
| 标两处以上重音 | 拒绝；挑标题里说的那一处 |
| 不写口径、不写 n | 拒绝；问用户样本是什么 |
| 有正有负、要并排比较的数据 | 还不支持，明说；逐级加减的中间各级可正可负，照常画 |
| 白描 / 打印版 | 不支持；V6 只出屏幕用的图 |
