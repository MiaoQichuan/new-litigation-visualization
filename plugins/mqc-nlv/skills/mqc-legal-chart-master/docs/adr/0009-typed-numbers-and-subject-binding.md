# 0009 标题数字分类型、绑主语；中文约数按区间核

## 背景

外部测试（2026-10-03，50 题）暴露：

- 数字紧贴汉字时根本没被抽出（T020、T028）——「只许算、不许编」在最常见的中文写法下失效；
- 数字能推出、但安错了主语（「驳回率 41%」，41% 是全额支持的占比，T012）；
- 百分点与百分比混用（「提高 20%」，T013）；
- 中文约数与数据明显矛盾（41% 写「九成」，T014），ADR 0003 定的是「不核、列请核」。

## 决定

1. **全模块只有一处抽数字**（`numtokens.py`）。边界只看 ASCII 字母、数字、下划线、小数点。
2. **派生数分三类登记**：num（件数、金额、差额、倍数）、pct（占比、增长率）、pp（百分点差）。
   数据本身是百分比（`unit: "%"` 或百分比模式的百点方阵）时，两值之差登记为 pp。标题里带 % 的只对 pct 核。
3. **主语绑定**：每个派生数记下它说的是哪个数据 id。标题数字所在分句里有类目名时，这个数必须属于这个类目；
   属于别的类目就拒，并指出属于谁。只在「对不上本类目、却对得上别的类目」时拦，减少误拦。
4. **中文约数按区间核**（修订 ADR 0003）：区间放宽到「一成」的一半，图上没有一个数落在区间里才拒；
   对上了仍列请核。
5. 年份须在口径、来源、类目里；条文编号与案号不核、列请核。

## 否掉的替代方案

- **只把 `\w` 换成 ASCII**：能修 T020，修不了 T012–T014；而且各处各写一个正则，下次还会漏。
- **直接上 `claims` 结构化结论**：要求说明 JSON 改形，与 V7 模块清单一起定更稳（见处理记录第四节）。
- **中文约数继续不核**：T014 证明「列请核」在实际使用里会被跳过；明显矛盾的就该拦。
