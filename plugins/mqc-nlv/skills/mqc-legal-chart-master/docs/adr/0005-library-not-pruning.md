# 0005 建场景库，不砍候选

## 背景

最初的做法是列一批候选图，由作者逐张「留 / 砍」。作者否掉了：不同律师讲的东西差别很大，
我们替他砍掉的，正好可能是他要的。应当保留尽可能多的场景，由使用者在用的时候选。

## 决定

把「场景」和「画法」拆成两层。

- **场景**是数据：一行说明这页图回答什么问题、要什么数据、用哪种画法、有什么法律上的特别守卫。
  可以无限扩，加一行不写代码。
- **画法**是代码：渲染器加守卫。数量有限（二三十种），几百个场景都落在它们上面。

使用时由 `find.py` 检索，模型只读命中的几条，库再大也不多花 token。

## 开发顺序

不再逐张砍，改为统计：每种待建画法被多少个场景用到，用得多的先做（`find.py --forms`）。

## 仍然保留的提醒

不砍不等于不提醒。涉及执业规范或合规风险的场景（结果预判、胜诉率宣传、地图）照样收录，
但画法标「慎用」或在守卫一栏写明风险与替代做法，由使用者知情后自己决定。

## 否掉的替代方案

- **逐张投票砍。** 砍掉的是别人的需求。
- **模型每次读完整个库再挑。** 库一大就费 token，也容易挑花眼。
