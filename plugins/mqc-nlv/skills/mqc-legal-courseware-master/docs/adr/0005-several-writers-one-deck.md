# ADR 0005：几方同时写同一套课件

状态：已采纳（0.8.4）

## 背景

一套课件同时有几方在写：编辑器（可能开着两个窗口）、对话里的 AI（`ai.py apply`）、命令行。
它们共用两份文件：`deck.json`（课件）与 `ai/requests.json`（请求队列）。

0.8.3 已经处理了「两个编辑器窗口前后脚保存」：保存带着最后看到的版本，磁盘上被改过就按页合并。
这一版实测又发现两处：

1. **写文件会互相踩。** 暂存文件名是固定的 `<文件>.nlv-new`。两个进程同时写同一份文件时，一个改名时把另一个
   还没写完的暂存文件搬了过去，读到的是半个文件。实测四个进程各记 25 条请求：只剩 29 条，有进程读到空文件崩掉，
   还有一次请求文件被写成两份 JSON 首尾相接，编辑器再也读不了队列。
2. **AI 交回的结果「改不到没有为止」。** 交回的页拼出来还有要改的（大数字推不出、法条没写原文），原来照样写进去、
   请求算「做好了」；AI 改好再交，被拒（「已经是 done」）。SKILL.md 写的循环做不到；加页类的请求即便能再交，也会越加越多。

## 决定

1. **课件文件夹一把写锁。** `scripts/safewrite.py` 的 `lock(folder)`：读—改—写整段持锁。
   用系统的文件锁（POSIX 的 `flock`、Windows 的 `msvcrt`），进程退出由系统放锁，不会因为谁崩了就永远锁死；
   锁文件 `.nlv-lock` 一直留着、从不删除（有的沙箱不许删文件）。同一线程嵌套持锁不会自己卡住；半分钟拿不到就报错，不无限等。
   持锁的有：记请求、改请求状态、AI 交回结果（从读课件到写课件、改状态整段）、编辑器保存（核版本与写入之间）。
2. **暂存文件各用各的。** 名字带进程号与线程号，改名覆盖，仍不靠删除。
3. **请求要能改到没有为止。** 交回的结果过了校验但拼出来还有要改的：写进去让用户看见，请求留在「正在做」，
   note 写明还有几处要改；AI 对**同一个请求**再交，加页类换掉上次加的那几页（请求里记着 `made`），不越加越多。
   改不了的（缺用户的原文、材料）由 AI 用 `done --note` 收尾、说清缺什么。没过校验的仍然整份拒绝，课件不动。
4. **请求自带交回的写法。** `wait` / `list` 给出的上下文里有 `answer`：这一类请求该交回什么，以及照抄就能跑的
   `take` / `apply` / `fail` 命令（脚本与课件都写真实路径）；出图请求另给那个模块 SKILL.md 的路径。
   读上下文的模型不必回头翻 SKILL.md，换一个能力弱一些的模型也照样做得对。

## 不做

- 数据库或常驻的协调进程：只用标准库与文件，编辑器关了、换一台电脑，课件文件夹拷走就能接着做。
- 给每个请求开单独的结果文件：队列仍是一份 `requests.json`，加锁之后不再丢。
- 删除旧锁文件或暂存文件：一律改名覆盖。
