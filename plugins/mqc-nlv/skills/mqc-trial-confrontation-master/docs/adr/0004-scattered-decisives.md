# ADR 0004 — 争点零散时不排序、不封顶

**状态：** 已采纳

## 背景

L4 原规定全图深红 1–2 处，算出超过 2 处即报错拒绝出图。
一件真实的买卖合同仲裁把它撞穿了：申请人五项请求加被申请人反请求，
其中质量违约金、延误维修违约金、损失赔偿三项同时命中 D1 的三条判据——
都有争议、客观证明责任都在请求方、现有证据都未达证明标准。
L3b 的从属性排除只能排掉维权成本与仲裁费，排不掉这三项里的任何一个，
它们各自都是独立的胜负手。按旧规则这个案子根本出不了图。

## 否掉的替代

**由代码排序取前二。** 违反 A2：决定性要件排序明文属于「只给方向，结论留空等律师填」。
代码替律师挑出最要紧的两个，就是替他下了那个他本该自己下的结论，
而下游按前景排序、按争点分组时不会去区分那行小字。

**上限跟对抗部分数挂钩**（如每三个部分许一处深红）。凑出来的数，没有法理依据。

## 决策

判定照算，不封顶，如实写进表的 decisive 列。图上至多强调 2 处；
算出三处及以上转入分散态：全图不用深红，索引表仍如实标出命中项，
底部结论条改写成「胜负手分散 · 共 N 处：P1 / P2 / P3」。

## 理由

L4 要封的是视觉强调的密度，不是断言一个案子只能有两个胜负手。
争点零散的案子本来就没有唯一胜负手，硬指一处反而误导律师。
把「有几处」如实说出来，比挑一处说「就是它」更接近这张图的用途。

## 代价

分散态下这张图失去单点指向性，退回成索引。这是如实的代价，不是缺陷。

## 后记（措辞统一）

「胜负手」是围棋用语，不合律师的说话习惯。全套统一改用「决定性要件」——
它本来就是 D 组判据算出来的那个 element，也是请求权基础方法里的标准表述。
本文正文保留当时的原话，实现中的文案已改为：单处「决定性要件 · P1-1 ……」，
分散态「决定性要件 N 处，争点分散：P1 / P2 / P3」。
