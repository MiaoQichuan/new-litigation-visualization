# ADR 0007 — 适用边界、攻击性防御与立场参数

**状态：** 已采纳

## 背景

这三条来自两份外部 skill 的对照：缪奇川《请求权基础·要件审判九步法（律师版）》，
以及陪跑营学员的《被告代理打法手册》。对照之下，本 skill 有三处不是风格问题，是学理硬伤。

**一、适用边界。** 请求权基础分析锚定给付之诉。确认之诉与形成之诉的规范结构不是
「要件 → 给付效果」，而是某个法律状态是否存在、某项形成权能否有效行使；
拆要件等于把方法用在它失灵的地方。而本 skill 的诉请封闭表里摆着「确认」「形成」两个类型，
照常往下拆。示例数据自己就撞在这里：诉请一是「形成·解除合同」，却被拆成了构成要件。

**二、攻击性防御。** 反诉、抵销、违约金过高请求酌减、另案主张这四项不是抗辩，是反攻。
它们不否认事实、不阻却权利发生、不使权利消灭、也不是拒绝履行的抗辩权，
而是另起一条独立的权利主张。硬塞进四分法必然归错——抵销会被归成「权利消灭」，
可它针对的是全案而不是某一个要件。真案子里撞到过两次（一件仲裁、一件借款返还），
当时记成「整案层面抗辩暂不改」，答案其实在这儿：不是要给它一个新位置，
是它本来就不属于抗辩那张表。

**三、立场。** 九步法的铁律是立场参数翻转全程读数、且客观研判与立场打法物理分离。
本 skill 一个立场字段都没有，可 D1 算的是「提出请求的一方证不出」——
那对抗辩方是好消息、对请求方是警报。同一张图两种读法，图上却看不出是给谁做的。

## 决策

- 诉请为确认 / 形成的，必须填 `boundary` 写明转法律关系分析法，且不得拆成构成要件（E1、E2）。
  混合诉切分处理：给付部分照常跑。
- 四项攻击性防御移出 `response_class`，单列在 `case.counterattacks`，各写处理路径（G1–G3）。
- `case.stance` 标明原告向 / 被告向，写进图头；每条要件带 `direction` 立场方向标（T1、T2）。
  图上只呈现客观研判，攻防着力点与诉请设计不进此图。

顺带补齐同源的三条：程序站必须逐项审查管辖 / 主体 / 重复起诉（P1，防单方材料直通全胜）；
材料成熟度 L0–L3，L0/L1 下不对争议要件下硬判断（M2）；
决定性要件必须落到「若维持真伪不明，由负客观证明责任的某方承担不利后果」这句标准表述（D1）。

## 理由

前三条各堵一种学理错误：边界挡「把方法用在它失灵的地方」，
攻击性防御挡「归类归错导致举证责任算错」，立场挡「客观与打法混用」。
后三条是同一套纪律的延伸：先过程序站再谈实体，材料薄时降精确度而不降结构，
决定性要件的结论必须锋利到可执行。

## 代价

casefile 要填的东西变多了。但这些本来就是律师脑子里已有的判断，
填不填得出来，恰好是他对这个案子有没有想清楚的检验。

## 后记（四处返工）

吸收外部方法的当轮就改坏了四处，记下来：

1. **材料成熟度纪律污染了判定。** 原实现是「L0/L1 下争议要件的证明前景一律标待定」，
   可证明前景正是决定性判定的输入。实测：97 万元借款返还案标成 L1 后，一处要件的前景
   由「低」改成「待定」，分析表里仍标决定性、图上却不再强调，图表就此不一致。
   改为：判定照算照标，降的是证据置信（必须为低）并强制列明待补材料。
   九步法原话是「降级只降精确度，不降结构」——第一版把它实现反了。
2. **程序站靠数关键词。** 要求那段话里出现「管辖」「主体」「重复起诉」三个词，
   于是写「双方均为适格当事人」明明审过主体却判不过。改为三项分列成字段。
3. **真伪不明的结论塞进了中轴卡的正文。** 那句标准表述本该进分析表，
   塞进 `court_standard` 会让每个决定性要件的卡都拖一行套话，图先被拖垮。
   另立 `burden_conclusion` 栏，只进表不进图。
4. **E2 查了一个谁都没填的字段。** `claim_ref` 当时并不存在于任何数据里，
   判据恒真，等于没写。改为：边界诉请对应的对抗部分必须标 `method: 法律关系分析法`。

连带发现一处旧漏：图表一致性检查写死只跑示例，真案子上从未查过——
第 1 条的不一致正是这么漏掉的。已改为可跑任意 casefile，并接进管线，出图前必过。
