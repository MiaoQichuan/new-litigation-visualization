# ADR 0005 — 行组的单位是争议要件，不是诉请

**状态：** 已采纳

## 背景

`to_figure` 原先每个对抗部分只取一条要件进图：有多条「有争议待证」时取标为决定性的那条，
否则取第一条。示例数据里每个部分恰好只有一条争议要件，这个取舍一直看不出问题。

一件真实的借款返还纠纷把它撞穿了。原告只有一项诉请——返还 97 万元，
但争议要件有两条：一是款项定性为借款还是合作合同解除后赔偿方案项下的预付，
二是协议约定的「最终赔偿方案确认后多退少补」这一条件是否成就。
被告的实质抗辩全部落在第二条上。按旧写法图上只画得出第一条，
对方唯一的抗辩整个消失，而分析表里两条都在。图与表就此对不上，
且这种对不上没有任何判据抓得住——X1 当时比的是对抗部分编号，两边都是 P1，照样通过。

## 决策

一个「有争议待证」的构成要件占一个行组。同一诉请下有两条就出两个行组。
行组编号用要件编号，标题为对抗部分名加要件名，索引表第一列改用编号。
无争议的要件（默示满足、隐含前提）不进图，只在表里留痕。

## 连带

X1 的判据随之改写：从「对抗部分编号一致」改为「表里每一条有争议待证的要件都进了图，
图上不得出现表里没有的」。这条比原来的更贴近它想守的东西。

## 代价

争点多的案子行组数变多，图更长。这是如实的代价：争议要件有几条，图上就该有几组。
真正需要控制的是视觉强调的密度，那件事由 L4 的分散态负责（ADR 0004）。
