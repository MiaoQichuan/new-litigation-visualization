# 庭审对抗图大师 · 常见问题、报错对照与限制

遇到问题先看这一份：常见误用、报错怎么办、本诉与反诉怎么放、术语速查、已知限制、隐私与合规都在这里。

## 一、三步上手

    python3 <本技能目录>/scripts/pipeline.py --check          # ① 看本机能出什么（Excel、SVG、PNG）
    python3 <本技能目录>/scripts/pipeline.py --demo           # ② 用随包示例跑一遍，产物在 ./庭审对抗图-示例
    python3 <本技能目录>/scripts/pipeline.py 我的案件.json 出图  # ③ 换成您自己的案件

第 ③ 步的 `我的案件.json` 不必手写：在 AI 助手里说「用庭审对抗图大师，把这个案子的争点推一遍」，
把起诉状、答辩状、证据目录交给它，它按 `references/casefile-guide.md` 的次序填好、自查、出图。
自己填时照该文件第 4 节「可粘贴骨架」起头，完整示例是 `examples/matrix-input.json`。

交付物默认是**分析表 Excel + 对抗图 SVG**，两样任何电脑都出得来。命令末尾可以再写一项选择：
`1`＝只要 Excel、`2`＝只要 SVG、`3`＝加 PNG、`全部`＝三样都要（例：`… 我的案件.json 出图 全部`）。

## 二、常见误用（反模式）

| 误用 | 会发生什么 | 该怎么做 |
| --- | --- | --- |
| 把它当呈报件交法院 | 图上有我方薄弱点、待补证、风险等级，等于替对方把观点摆上去 | 对内推演、向当事人汇报用；对外用法律关系图或时间轴 |
| 期待它给胜诉率 | 它不预测胜负 | 它摆出要件、举证责任、证明前景；结论留给律师 |
| 让它替双方写主张 | 四段攻防的正文只照录起诉状、答辩状、代理意见的原文 | 材料里没有的段填「—」，并在 scope 里说明为什么空 |
| 自己指定标红 | 深红由规则算出，不接受手指 | 规则见第五节「决定性要件」 |
| 把反诉、抵销写成抗辩 | G1 会拦下，四分法里不收这四样 | 写进 `case.counterattacks`；反诉另起一个对抗部分（见第四节） |
| 一个对抗部分塞多个争点 | 行组的单位是「一个有争议待证的要件」 | 一个争议要件占一个行组 |
| 争点写得太多 | 决定性要件算出三处及以上即为分散态，全图不标红 | 收敛到真正决定成败的一两处，其余留在表里 |
| 编条号、案号 | 违反红线 | 拿不准的标【待核验】并写检索方向 |
| 材料没读完就出图 | 完备性对账不平，拒绝出图 | 没有的写 `scope.not_obtained`，有但不读的写 `waived` |
| 把产物写进本技能目录 | 技能更新时整个目录会被替换 | 输出目录写在您自己的工作目录里 |

## 三、报错对照

所有报错都以「出错：」或「拒绝……」开头，说清是哪一步、怎么改；不会甩 Python 堆栈
（排查程序本身的问题时设环境变量 `NLV_DEBUG=1` 才看堆栈）。

| 您会看到 | 意思 | 怎么办 |
| --- | --- | --- |
| `用法：…`（退出码 2） | 没给案件文件 | 按提示补上路径，或先 `--demo` |
| `找不到文件 …` | 路径打错 | 核对路径；中文路径与空格都可以，记得加引号 |
| `JSON 写坏了：第 X 行第 Y 列` | 多了逗号、用了中文引号、少了括号 | 按行列号改 |
| `文件不是 UTF-8 文本` | 记事本存成了 ANSI，或给错了文件 | 另存为 UTF-8 |
| `输入的骨架不全，先补上再跑` | 缺 case、parts、claim_bases、elements 或要件字段 | 按逐条清单补；没有内容的段填「—」，不要删字段 |
| `拒绝出表：诉请固定或抗辩归类不合规` | 前端校验有 FAIL 行（见下表） | 只改 FAIL 那几行，重跑 |
| `拒绝出图：完备性对账不平` | 有材料该读没读 | 读完，或在 scope / waived 里如实表态 |
| `认不出的材料格式` | 摄入只认 PDF、图片、docx、纯文本 | .doc 另存为 .docx，.xlsx 另存为 PDF 或 CSV |
| `G3 通道用满` / `G4 落点用满` | 一栏的走线或落点排满 | 合并同类争点，或把次要争点移出本图 |
| `G5 穿越自证未通过` | 有走线会压到卡片或标签 | 一般是一侧卡片过多；按 L 组提示调四段收口 |
| `拒绝交付：图表一致性未通过` | 图与表对不上 | 重跑 pipeline（不要单独改 SVG） |
| `缺少必需的第三方库：openpyxl` | 出 Excel 要它 | `pip install openpyxl`；只要图就在命令末尾写 `2` |
| `PNG 没出成` | 缺 Pillow / numpy 或转图工具 | Excel 与 SVG 已照常交付；`--check` 看缺什么 |
| `本机没有能出 PNG 的工具` | 同上 | 装 cairosvg、Inkscape、LibreOffice 之一，或 `npm install @resvg/resvg-js` |

**前端校验的编号**（`check_claims.py` 打印的 FAIL 行）：

| 编号 | 查什么 | 常见改法 |
| --- | --- | --- |
| J1 / J2 | 诉请类型在封闭表内、必填项齐全 | 类型照骨架写；缺的必填项补上 |
| J3 / J3b / J3c | 钱款诉请附构成明细、合计平、每项有依据 | 差额作显式调整项，不改数凑平 |
| K1 / K2 / K3 | 抗辩归类在四分法内、举证责任随归类、写出三问路径 | 按 casefile-guide ⑥「三问速判」重走一遍 |
| G1 / G2 / G3 | 反诉等四样不混进抗辩、写明处理路径 | 移到 `case.counterattacks`，写清走哪条路 |
| T1 / T2 | 每条要件带立场方向、全案标明立场 | 填 `direction` 与 `case.stance` |
| D1 | 决定性要件写明真伪不明由谁承担 | 落到标准表述那一句 |
| E1 / E2 | 确认之诉、形成之诉标出边界 | 写 `boundary`，对应部分标「法律关系分析法」 |
| P1 / M1 | 程序站三项、材料成熟度 L0–L3 | 管辖／主体／重复起诉分列 |
| S1 / S2 | 空段有归因、同一文书不两说 | 写进 scope |

## 四、本诉与反诉放在同一张图

反诉不用另行整理，和本诉放在同一张图、同一份表里：

1. **在 `case.counterattacks` 里登记一条**：`{"kind": "反诉", "handling": "本案反诉，已交诉讼费……"}`。
   `kind` 只有四个值：反诉 / 抵销 / 违约金酌减 / 另案主张。它们是另起的权利主张，不是抗辩，不入四分法。
2. **为反诉另起一个对抗部分**：`label` 写「P3·反诉：继续履行」，`track` 写「反诉」。
   这一部分里「提出请求的一方」是被告，左栏放被告的主张，右栏放原告的回应，判据照常算。
3. **立场照常标**：反诉部分的决定性要件同样按三条判据算出，只是胜负方向朝向被告；
   对谁有利写在 `direction`，不和「决定性」混成一件事。

随包示例 `examples/matrix-input.json` 的第三个对抗部分（P3）就是反诉，抵销登记在 `counterattacks` 里，可以照抄改写。

## 五、术语速查（给不熟悉九步法的读者）

| 术语 | 一句话解释 |
| --- | --- |
| 请求权基础 | 支持这项诉请的法律条文（「凭哪一条要钱」） |
| 构成要件 | 这条法条要成立必须同时满足的几件事实 |
| 举证责任 | 这件事实真伪不明时，由谁承担不利后果 |
| 四段攻防 | 主张 → 回应 → 反制 → 再回应，按文书原文照录 |
| 抗辩四分法 | 否认 / 权利障碍抗辩 / 权利消灭抗辩 / 权利受制抗辩权；后三类举证责任在抗辩方 |
| 决定性要件 | 有争议 × 证明责任在提出请求的一方 × 证明前景为「低」或「存疑」，三条同时成立 |
| 分散态 | 决定性要件算出三处及以上：全图不用深红，改写明共几处 |
| 三标 | 每条要件带法律层面置信、证据层面置信、来源 |
| 材料成熟度 L0–L3 | 材料齐到什么程度；L0／L1 下不对争议要件下硬判断 |
| 程序站 | 先过管辖、主体、重复起诉三项，再谈要件 |

## 六、常见问题

**为什么是三栏？** 左为提出请求的一方，中为法院审查，右为抗辩的一方；一个争点板块占一个行组，同侧诸卡汇聚成母线进入中轴。

**分析表和图是什么关系？** 表是唯一的信息源，图由表派生；出图后由图表一致性检查逐项核对，图上看不清的回表查对应行。

**能只要图或只要表吗？** 能：命令末尾写 `2` 只出 SVG，写 `1` 只出 Excel。

**决定性要件为什么至多标两处？** 标红超过两处就失去指示作用；三处及以上转入分散态，在结论条里写明共几处。

**材料不全能出图吗？** 能。每处空段须在 scope 里表态（没有／未获取／明示不读），图底如实写明材料范围；只有「该读没读」会拒绝出图。

**扫描件、照片能读吗？** 能。PDF 先探测逐页文字，扫描页转成待读图由 AI 助手读；图片本身即一页待读图。

**同一份 JSON 每次出的图一样吗？** 一样。几何由版面约束反解，不含随机成分。

## 七、已知限制

- 这是**内部推演件**，图上写明不对法院出示。
- 不预测胜负、不给胜诉率；证明前景、决定性要件排序、法院另作定性的风险只给方向，结论留空等律师填。
- 确认之诉、形成之诉不按要件拆，标出边界后转法律关系分析法。
- 版面只有四种（左2右2 / 左2右1 / 左1右1 / 左1右0）；左1右2 不成立，会被拦下。
- 请求权基础定得对不对、要件拆得全不全没有机械判据，须律师自己过一遍。
- 摄入不认 .doc、.xlsx、.pptx，请先另存为 docx 或 PDF。

## 八、隐私与合规

- **不联网、不外传。** 本技能不调用任何外部接口、不需要凭据，只读您指定的材料、只往您指定的目录写文件。材料本身去了哪里，取决于您用的 AI 助手。
- **不脱敏。** 它不会替您隐去当事人姓名、身份证号、账号；涉密或敏感案件请先自行处理。
- **判断带标。** 请求权基础、要件拆解、抗辩归类会出，但每条带置信与来源；条号案号不编造，拿不准的标【待核验】。
- **交付前请复核。** 每次运行打印的核对清单就是给您逐项核对用的。

## 九、版本与变更

版本号在 `SKILL.md` 的 metadata 里，历次变更见同目录的 `CHANGELOG.md`。限制与边界一律写在 SKILL.md 与本页，不藏在变更日志里。
