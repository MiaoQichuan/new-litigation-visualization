# 法律关系图大师

庭前三大法宝之一。把案件材料推成一张法律关系图：
谁与谁、就哪份合同或哪段工程、发生了什么法律关系。

## 与另外两件的分工

```
大事记表大师　　时间线：什么时候发生了什么
庭审对抗图大师　争点：谁主张什么、对方怎么抗辩、法院审查什么
法律关系图大师　结构：谁与谁、就什么标的、成立何种关系
```

## 一眼看懂的三件事

**主体与客体并存。**只画当事人不完整——合同、工程、标的物本身就是模块，
法律关系要靠它们串起来。

**索引查表，不现算。**1 到 6 个主体的全部图形（143 张）已穷举并存好结果，
查到直接用，0.1 秒出图；再大的查候选参数。运行时不做推导。

**判据回读产物。**十三条判据读最终 SVG 的坐标，不信任内存里的理论值。
不穿主体、不贴边、箭头到位、色块圆角、强调至多两处，都验过才交付。

## 快速开始

模型只写一份 `relations.json`（写法见 `references/relations-guide.md`），其余交给脚本：

```
python scripts/make.py --check                                   查环境
python scripts/make.py relations.json --plan-only                规模判断，一秒内返回
python scripts/ask.py round1                                     问交付给谁，定风格
python scripts/make.py relations.json --out 目录 --choice choice.json
```

一条命令出齐：布局、渲染、所选风格、五种格式、路线判据、导出物判据、出处索引、交付说明。
提问的完整流程（第〇轮精简、第一轮风格、第二轮重点）见 SKILL.md。

## 规模边界

```
模块不超过 9 个、关系不超过 12 条　　默认上限，超限先走第〇轮由使用者精简
1 到 6 个主体　　完整图索引，查到的是结果
7 到 9 个　　　　度序列特征组，391 条
10 到 16 个　　　结构特征分档，60 条（使用者要求全部保留时）
超过 16　　　　　告知拆图
最大度超过 12　　告知拆图，不做尝试
```

边界不是拍的：6 是暴力枚举图的极限，9 是度序列索引的性价比拐点，
16 是已验证的规模上限，12 是单个模块的端口容量。
9 个模块、12 条关系以内，布局实测几秒；超过之后耗时与交叉数成倍上升。
