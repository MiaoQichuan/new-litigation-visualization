# relations.json 怎么写

模型在这个 skill 里只写这一份文件。布局、渲染、导出、判据全部交给
`scripts/make.py`，不要读 scripts 里的源码，也不要另写生成脚本。

## 格式

```json
{
  "slug": "case01",
  "title": "某某纠纷 · 法律关系图",
  "sources": ["判决书.pdf"],
  "nodes": [
    {"id": "ZHAO", "name": "张某", "note": "被上诉人", "kind": "主体", "source": "判决书第2页"},
    {"id": "AGR1", "name": "《投资协议》", "note": "2015年8月1日", "kind": "客体", "source": "判决书第5页"}
  ],
  "edges": [
    {"from": "ZHAO", "to": "AGR1", "label": "签订", "line": "实线", "source": "判决书第5页"}
  ],
  "unsure": ["某丙公司的持股比例判决书前后表述不一，第6页写60%，第9页写65%"]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| slug | 否 | 产物文件名前缀，只用英文数字，缺省为 relation |
| title | 否 | 图标题 |
| nodes[].id | 是 | 英文数字，全图唯一 |
| nodes[].name | 是 | 照录原文，一个字不改；放不下脚本自动换行、自动加高模块 |
| nodes[].note | 否 | 诉讼地位或一句身份说明，一行放得下（约 12 个字以内）；名称加备注超过两行，全图改用高模块，布局慢三到四倍 |
| nodes[].kind | 否 | 主体（当事人）或客体（合同、工程、股权、款项），缺省主体 |
| edges[].from / to | 是 | 主体 id，箭头指向 to |
| edges[].label | 是 | 关系名照录原文，不许空着 |
| edges[].line | 否 | 实线（主体与客体之间的行为）或虚线（客体之间的指向、从属、历史状态） |
| source | 否 | 出处，写进出处索引 |
| unsure | 否 | 读不准的，原样列出，交人工确认 |

旧写法 `"edges": [["ZHAO", "AGR1", "签订"]]` 也认。

## 不写什么

重点不写在这里。风格与重点只认 `ask.py resolve` 给出的 choice.json，
relations.json 里写了也不用。

## 只取要紧的

模块尽量不超过 9 个，关系尽量不超过 12 条。这是出图快慢与清楚与否的分界：

| 同一个股权案 | 耗时 | 交叉 |
|---|---|---|
| 15 个模块 21 条关系 | Windows 上半小时以上 | 14 处 |
| 9 个模块 17 条关系 | 31 秒 | 12 处 |
| 9 个模块 12 条关系 | 6 秒 | 0 处 |

取舍的顺序：当事人先保；本案争议指向的合同、股权、款项次之；
只起背景作用的公司、历次登记变更、与争点无关的关联方放进 unsure
或干脆不列。

**关系按重要性从高到低写。**超过 12 条要精简时，脚本按这个先后给建议。
同一方向、同一对模块之间的几种关系会自动合成一条（关系名用「；」连起来），
不必自己合并，也不要为了凑数删掉关系名里的字。

## 规模先看一眼

写完先跑 `make.py relations.json --plan-only`，一秒内告诉你能不能画。
超过 9 个模块或 12 条关系时它会停下，提示先跑第〇轮（ask.py trim），
由使用者定留哪些，不要自己反复增删去试布局。
