# ADR 0001 — 扫描件走「探测 → 栅格化 → 模型读图」，不引 OCR 依赖

**状态：** 已采纳（2026-08-19）

## 背景

律师给的材料几乎总有扫描件与照片，对方提交的那部分尤其如此。`HANDOVER` 147 行早已定过
方向：不读图就永远只看得见一方，而**只看见一方的时间轴恰恰是最危险的产物** —— 它看起来
完整，实际是单方陈述。

实测的材料形态：一份 20 页原告证据（逐页可读字符全部为 0、每页一张整页 JPEG）、
两份 6 页扫描合同、两张微信与付款计划照片、一份含 35 张截图的 docx。

## 决策

三步，用 poppler 自带命令，**不装模型、不调 API**（`scripts/read_image.py`）：

    probe（逐页量可读字符）→ rasterize（pdftoppm -jpeg -r 150）→ 模型逐页看图

做法取自 Anthropic 官方 `pdf-reading` skill 的原话：扫描件「`pdftotext` 什么都不会返回，
别跑它。把页面以 150 DPI 栅格化，然后视觉读取」。

**探测的判据是「逐页可读字符数」，不是「`pdffonts` 有没有字体」。**

## 否掉的替代

- **引入 OCR 引擎（pytesseract / PaddleOCR / GLM-OCR）。** 与项目零依赖的路线冲突；
  而且各家 harness（Claude Code、Codex、Cowork、DeepSeek Harness）的模型不同，
  装引擎等于给每家准备一套。栅格化那条路模型强就读得准、弱就读得差，**流程不变**。
- **拿 `pdffonts` 空表当判据**（官方 skill 的原话）。真材料上有反例：一份 20 页扫描证据
  `pdffonts` **不是空表**（第 20 页挂着一个空字体），而逐页可读字符全部为 0。
  照那个判据会把扫描件当文字型，一个字都读不到。
- **自己写坐标聚类解析表格**（按 x 直方图找空白走廊、按编号锚归行）。走过一遍：投影法只
  找到页边距两条走廊；改用左边界聚类分列成功（四列 57/90/259/303），但**行界怎么都对不上**
  ——那份 PDF 四列的垂直对齐方式不同（编号居中、正文顶端对齐），任何单列锚都必然偏。
  这条路做到一半发现方向错了：该做的是让模型直接读图。
- **拒绝扫描件。** `RELAY-1` 45 行原本就是这么定的，已被 `HANDOVER` 147 行推翻。
- **分级读（先读目录页决定读哪些页）。** 它的前提是「有目录页」，而多数扫描件没有
  （一叠合同、一堆回单、几十张截图）。拿一份材料的特例当通用策略，会漏页且没人知道。
  改成只报预估成本（约 1600 token/页），**要不要全读由律师定，代码不替他挑页**。

## 执行处

`tests/run_checks.py` 的「扫描件与照片：读图这条路的账目」一节：探测必须逐页量字符
（正反两向：文字型判 `text_layer`、纯图判 `scanned`，样本用 reportlab 与 img2pdf 就地生成）。

## 后果

- 页数多时会占掉很大一块上下文（20 页约 3.2 万 token，300 页超出多数模型）。
  这是明摆着的代价，由律师决定要不要全读。
- 模型的 OCR 能力直接决定读得准不准，代码管不了。可核验性靠 ADR 0002 那套账目。
