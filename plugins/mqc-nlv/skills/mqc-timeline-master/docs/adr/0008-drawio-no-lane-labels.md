# ADR 0008 — drawio 导出不补侧标签，但守住 SVG / PPTX / VSDX 三种

**状态：** 已采纳（2026-08-19）

## 背景

一轮深度自检量出来的：五种可编辑格式里，**SVG / PPTX / VSDX 三种都有侧标签
（「原告主张 / 被告主张」），drawio 一律没有** —— 三份带泳道的示例全部如此。

（追查过程里有一次误判值得记：一开始以为只有一份丢、另两份不丢，后来发现那两份的
「不丢」是假象 —— 它们的侧标签字样恰好出现在卡片正文里（「甲公司、乙公司出具沟⋯」），
被探针当成了侧标签。**按字符串在整份文件里搜，会把正文里的巧合当成目标元素。**）

原因不是坏了：**v1 的 `export_drawio.py` 从来不知道泳道的存在** —— 那份 564 行的建模器
里一处 `lane` 都没有，v1 自己的八份示例也没有任何图用泳道。泳道是 v2 新增的能力。

两条路的差别在这里：
- `export_pptx` / `export_vsdx` **读最终 SVG 逐元素转**（前者开头写着 transcribe the
  master SVG instead of re-deriving the layout，因为 SVG 是这个 skill 的正典产物），
  所以 SVG 上有什么它们就有什么 —— 侧标签自然带过去了。
- `export_drawio` 从**语义地图重新建模**，v1 的建模器不认识 `lanes`。

## 决策

**不补 drawio 的侧标签。** 把这条边界在 `export_formats.py` 的文档串里说清
（原来只写了「drawio 不是那张图的另一种存法」，没点明侧标签在其中）。

**守卫盯另一头**：SVG / PPTX / VSDX 这三种**必须**有侧标签，丢了当场报。

## 否掉的替代

- **改 v1 的 `export_drawio.py` 让它支持泳道。** 要动 v1 那 564 行建模器，
  给它加一个新的几何维度（它的摆放自成一套，见 `_positions_layered`）——
  而 v1 是冻结的、已发布的、同行认可的。这是重写级别的改动。
- **把 drawio 也改成读 SVG。** 那就是重写一种格式，而 `export_formats.py` 开头
  「**不要在这里重写任何一种格式**」那条正是为此写的，理由也写在那里：
  「从零重写会无声丢掉想清楚过的东西（日期型从零写过一次，丢了刻度尺、
  擅自加了圆点、卡宽被改）」。
- **在 v2 侧给 drawio 的产物后期补两个文本单元。** 想过，否掉：那等于在 v2 里写
  半个 drawio 建模器，位置要自己算（drawio 的摆放与我们的 SVG 不同），
  算错了比没有更糟 —— 一个位置不对的侧标签会指向错的一侧。

## 为什么代价与收益不成比例

主交付物没问题：律师开庭用的 SVG、贴 Word 的 PNG（出自 SVG）、讲课用的 PPTX、
在 Visio / WPS 里改的 VSDX，**四种全都有侧标签**。drawio 是「拿到 draw.io 里继续改」
的载体，少两个侧标签不影响那个用途，而且**分侧本身在 drawio 里仍看得见**
（卡片仍分列在轴的两侧）。

## 执行处

`tests/run_checks.py` 的「侧标签必须活到 SVG / PPTX / VSDX 三种交付物里」一节。
改坏验证两个方向全部抓住：整段侧标签不画、只画上侧丢下侧。
`scripts/export_formats.py` 的文档串写清了 drawio 这一条是**明写的例外**。

## 后果

- 以后若有人给 v1 的 drawio 建模器加了泳道支持，可以来修订这一条，
  并把守卫的 `_want` 集合加上 drawio。
- 这一条同时是一条方法记录：**按字符串在整份文件里搜元素，会把正文里的巧合当成目标**。
  查产物里「某个元素在不在」时，要按元素的角色查（侧标签是贴左边缘、字号 12、
  font-weight 600 的那两个 text），不要只按文字内容搜。
