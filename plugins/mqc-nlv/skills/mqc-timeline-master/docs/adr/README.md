# 决策记录（ADR）

一件事**为什么这么定**、当时**否掉了哪些替代方案**。

## 为什么要有这一层

仓库里原来有两层：`HANDOVER.md` 第五部分是**已定的规矩清单**（结论），第七部分是
**本轮推翻的结论**（变更）。中间缺一层：**当时考虑过哪些做法、为什么选了这个、
排除了什么**。

缺了这一层的代价是实测出来的：在几十轮的接力里，同一件事被重新讨论过多次 ——
扫描件能不能读（讨论三轮，而 `HANDOVER` 620 行早就写着「只跑过有文字层的 PDF 与 TXT」）、
侧标签的字怎么定（两轮）、要不要给 `lane` 加字段。每次重新讨论都要重新做研究、
重新撞同样的坑。**结论看得见，被排除的方案看不见，就会有人再走一遍。**

这个做法学自开源项目 `diagram-design`（也是一个 agent skill）。它把已定决策写成编号短文，
README 里一句 **read them before relitigating one**（重新讨论前先读它）。
它那份 ADR 0005 还给出一句值得逐字记住的话：**只活在文字里的规矩，就是会发出坏示例的规矩**。

## 怎么用

- **动手之前**：要改的东西如果落在某条 ADR 的范围内，先读那条。想推翻它，先读
  「否掉的替代方案」那一节 —— 多半你想的那条已经被试过并写了失败原因。
- **定了新决策**：新增一条，编号顺延。不要改旧条的 Decision（那是历史）。
- **决策变了**：在旧条尾部加 `## 修订`，写清什么时候、因为什么、新结论是什么。
  **不许悄悄改判据而不修订这里** —— 判据是这条 ADR 的执行处，改了判据却不改这里，
  等于让那段代码悄悄成了权威。

## 格式

    # ADR 000N — 一句话结论
    **状态：** 已采纳（YYYY-MM-DD）
    ## 背景        什么材料、什么现象逼出这个决策；有实测数据就写数字
    ## 决策        一句话说清定了什么
    ## 否掉的替代   每条写「方案 + 为什么不行」，这一节是这份文档的价值所在
    ## 执行处      哪条判据／哪个守卫在管它（没有就写「仅文档，无判据」并说明为什么）
    ## 后果        代价是什么、以后哪种情况要回来重看
