# 字段说明

## 一、「事实.json」：Agent 写的部分（make.py 的输入）

与下文「底稿」的字段相同，只有两处不同，都是为了不重抄原文：

**materials** 每项用 `src` 指向「清单.json」里的源文件（S01、S02……），原文由脚本按行取：

| 字段 | 说明 |
|---|---|
| `src` | 源文件编号 |
| `from` / `to` | 只取其中第几行到第几行（一个文件里装着几份文书时用来拆开）；不写就是整份 |
| `lines` | 只在原文要你自己识读时写（扫描件、照片、乱码页）；写了就以它为准，`ln` 按它的行号算 |
| 其余 | `name` `kind` `sub` `side` `date` `dsrc` `evno` `stage` `confirm` `sameAs` `background` `tags` 同下文 |

**recs**（以及 claims、attention、arith、ctx 里的引语）可用行号：

| 字段 | 说明 |
|---|---|
| `ln` | 原文行号（txt 里每行前面的编号；用 `from`/`to` 拆过的材料也按源文件的行号） |
| `q` | 可不写，不写则整行即引语；写了只需与原文相差空格、全半角，脚本会按原文改正 |
| `qx_ln` | 补充引语的行号（数组），日期或金额在另一行时用 |
| `loc` | 可不写，自动写「第几页 第几行」；判决书里的诉称、辩称、质证、拟证明段落要写明 |

**checks**（只在「事实.json」里有）：要核对的算式。

| 字段 | 说明 |
|---|---|
| `title` | 核对什么，如「七笔抵顶之和应等于房源全额」 |
| `expr` | 算式，只用数字和 + - * / ( )，可带千分位逗号 |
| `equals` | 材料上载明的结果 |
| `tol` | 允许误差，默认 0.005 |
| `d` `ln` | 结果载于哪份材料哪一行（对不上时，待审卡片里显示这一行原文） |

脚本算出结果：对得上的只记入运行记录；对不上的生成一条 `arith`，页面列入待审「数字对不上」。

脚本拼出的底稿就是下文的格式，页面读它、页面存回的也是它。

---

## 二、底稿字段（v8-base/1）

底稿是一个 JSON 对象。页面读它，页面存回的也是同一个格式（另加 `decisions`、`changes`、`pending`）。完整范例：`examples/lending.base.json`。

## 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | 建议 | 固定写 `v8-base/1` |
| `id` | 是 | 案件标识，字母数字，如 `zhang-v-li-2024` |
| `title` | 是 | 案件名称，如「张三诉李四、王五民间借贷纠纷」 |
| `cause` | 建议 | 案由，如「民间借贷纠纷」 |
| `pack` | 建议 | 领域包：`general` 通用、`lending` 民间借贷、`construction` 建设工程、`sale` 买卖合同、`lease` 房屋租赁、`tort` 交通事故、`family` 婚姻家事、`labor` 劳动争议。决定事件类型的叫法和专属待审规则 |
| `program` | 否 | 程序，如「一审」 |
| `unit` | 否 | 金额 `amt` 的单位，默认「元」；范例里用「万元」 |
| `parties` | 建议 | 当事人：`[{name, role, short?, alias?[]}]`，`role` 写「原告」「被告一」等。称谓切换（姓名／诉讼地位／我方对方）靠它 |
| `actors` | 否 | 主体泳道：`{"P1":"张三（出借人·原告）", ...}`；事实里用 `act:["P1"]` 引用 |
| `actorOrder` | 否 | 主体泳道的顺序 |
| `materials` | 是 | 材料，见下 |
| `facts` | 是 | 事实，见下 |
| `claims` | 否 | 诉讼请求、主张（不当作事实） |
| `relations` | 否 | 材料写明的事实之间的指向 |
| `threads` | 建议 | 事实经过的线索分组 |
| `inferences` | 有推断时必填 | 推断日期的类别与依据 |
| `attention` | 否 | 需留意的地方（如签字栏空白），进待审 |
| `dupCandidates` | 否 | 你认为可能是同一件事的两个事实：`[["F03","F07","理由"]]`；页面也会自动找 |
| `arith` | 否 | 你核出的算术问题：`[{id, d, loc, q, title, why}]`——`d` 材料编号、`loc` 位置、`q` 照录的那一行、`title` 一句话写哪里对不上、`why` 写出算式与差额。大写小写金额不一致页面会自动找；加减乘除的核对要你自己算好写进来 |
| `note` | 否 | 关于材料的一句说明 |
| `decisions` `changes` `pending` | — | 页面写入，见文末 |

## materials（材料）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `L-01` 起编，唯一 |
| `name` | 是 | 材料名，如「借条」「民事起诉状」 |
| `kind` | 是 | `record` 书证 / `edata` 电子数据 / `statement` 当事人陈述 / `testimony` 证人证言 |
| `sub` | 建议 | 文书类型，如「借条」「银行转账回单」「微信聊天记录截图」 |
| `side` | 建议 | 出自哪一方，如「借款人出具」「原告提交」 |
| `date` | 建议 | 文书日期（落款日），照原文写，如「2023年3月1日」；**不要用文件的保存日期** |
| `dsrc` | 建议 | 文书日期取自哪里，如「落款」「交易日期」 |
| `evno` | 否 | 证据编号，如「原证1」「被证2」；事实经过的引注优先用它 |
| `stage` | 否 | 这份材料出现在哪个阶段：0 接受咨询、1 谈案、2 庭前、3 庭审时、4 庭后、5 结案后 |
| `confirm` | 否 | 程序状态：未提交 / 已提交 / 已质证 / 法院认定 / 生效确认 / 未被采纳 |
| `lines` | 是 | 原文，逐行照录的字符串数组；可有一行 `#标题` |
| `medium` | 否 | `text` 或 `image`（扫描件、照片、截图） |
| `pages` / `read` | 建议 | 共几页 / 实际读了几页；页面「读取」列据此显示漏读 |
| `tags` | 否 | 标签，领域规则用，如 `["转账凭证"]`、`["收据"]` |
| `file` | 否 | 出自哪个原始文件，如 `judgments.docx`；一份文件拆成几份材料时必填 |
| `sameAs` | 否 | 本份是另一份材料的脱敏稿、复印件或另一版本，填原件编号；副本不得单独支撑事实 |
| `background` | 否 | `true` 表示不含案件事实的背景材料（法条摘录等），没有记载引用也不提醒 |

## facts（事实）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一，如 `F01`；编号永不回收 |
| `t` | 是 | 事件类型：`comm` 沟通往来、`meeting` 会议与会谈、`agree` 协议或约定、`pay` 款项往来、`perf` 履行、`notice` 通知与催告、`decision` 决定与审批、`filing` 诉讼程序、`other` 其他；民间借贷包另有 `guar` 担保 |
| `title` | 是 | 中立的短标题，15 字左右；引用原话用「」，「」里的字必须能在出处原文里找到 |
| `state` | 否 | `occ` 已发生（默认）/ `agr` 约定、应当发生 / `est` 推定 |
| `key` | 否 | `1` 表示关键事实 |
| `role` | 否 | 事实角色，领域规则用，如「借款交付」「还款」（见各领域包） |
| `act` | 否 | 涉及的主体，引用 `actors` 的键 |
| `narr` | 否 | 事实经过里的叙述句主干，如「张三向李四交付借款」；不写则用标题 |
| `recs` | 是 | 记载，至少一条，见下 |
| `ctx` | 否 | 与此事相关的合同条款等背景引语：`[{d, loc, q}]`，冲突卡里会并排列出 |

### recs（记载：这件事在某份材料里怎么写的）

| 字段 | 必填 | 说明 |
|---|---|---|
| `d` | 是 | 材料编号 |
| `loc` | 建议 | 在材料里的位置，如「正文」「第3页第2段」「3/3 16:20 张三」 |
| `q` | 是 | 引语：原文里连续的一段原话，必须逐字照录，且包含 `raw` |
| `qx` | 否 | 补充引语（数组），日期或金额在另一行时用 |
| `raw` | 有日期时必填 | 日期在原文里的写法，如「2023年3月1日」「3/3 16:20」「腊月二十前」 |
| `s` | 有日期时必填 | 公历日期 `YYYY-MM-DD`；只有 `p` 为 `month` 时可写 `YYYY-MM` |
| `e` | 区间时必填 | 止日 |
| `p` | 是 | 日期精度：`day` 到日 / `month` 仅到月 / `range` 起止区间 / `approx` 大致日期 / `arange` 大致时段 / `none` 无日期 |
| `amt` | 否 | 金额数字（单位见 `unit`） |
| `inf` | 推断时必填 | 推断类别的键，对应 `inferences` |
| `sus` / `susWhy` | 可疑时必填 | 日期本身不成立（如「2月30日」）时标 `1` 并写原因 |
| `loose` | 否 | `1` 表示这条记载只是大致说法，不参与日期冲突比对 |
| `stmt` | 否 | `true` 表示这段是当事人的说法（如判决书里的「诉称」段）；`false` 表示虽然 `loc` 里有「陈述」等字样但其实是法院认定。不写时按材料种类和 `loc` 判断 |
| `nature` | 否 | 这笔金额的性质，如「结算款」「保理贴息」「押金」；同额不同性质会提醒 |

## inferences（推断日期）

```json
"inferences": {
  "Y": {"n": "原文未载年份", "basis": "微信记录注明「2024 年以前的消息」；与回单日期吻合，推定为 2023 年。"},
  "MON": {"n": "原文为相对日期", "basis": "2024年3月5日为星期二，「下周一」推为 2024年3月11日。"},
  "LUNAR": {"n": "原文为农历日期", "basis": "2024 年农历腊月二十为公历 2025年1月19日。"}
}
```

## claims / relations / threads / attention

```json
"claims": [{"id":"P1","who":"原告","title":"诉请偿还本金33万元及利息","d":"L-06","loc":"诉讼请求","q":"判令被告李四偿还借款本金33万元及利息","s":"2024-09-02"}],
"relations": [["LF01","LF03","出具借条 → 交付借款"]],
"threads": [{"id":"t1","title":"借款的成立与交付","facts":["LF01","LF02","LF03"]}],
"attention": [{"id":"A1","title":"签证单监理栏空白","d":"D-06","loc":"签证单","q":"监理单位意见：","why":"监理栏未签字。","ctx":[]}]
```

## 页面写入的部分

- `decisions`：律师在页面上的裁决（采信哪条记载、已确认、关键事实、疑似重复的分开或合并、待审的处理等）。更新底稿时**原样保留**。
- `changes`：改动记录。原样保留。
- `pending`：在页面里添加、尚未读取的材料：`[{mid, name, size, kind, doc_date, status:"尚未读取", text?, data?}]`。读完补进 `materials`、`facts` 后从这里删掉。
