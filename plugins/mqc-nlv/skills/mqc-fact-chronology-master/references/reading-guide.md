# 读材料、取事实的规矩

## 一、什么算一个「事实」

- 一件在某个时间发生（或约定要发生、或可推定发生）的事：出具借条、交付借款、还款、发催告函、签订合同、开工、停工、起诉……
- 一份材料里可能有很多件事；一件事也可能出现在很多份材料里。
- **同一件事只建一个事实**，各份材料的说法都挂在它下面作为记载。判断是不是同一件事，看：同一主体、同一行为、同一笔款项或同一份文件。日期、金额写得不一样，**恰恰要挂在同一个事实下**，页面才能把不一致找出来。
- 拿不准是不是同一件事的，分成两个事实，写进 `dupCandidates`，交给律师判断。
- 约定将来要做的事（如「借期至2024年2月29日」），建成 `state: "agr"` 的事实（「借期届满日」），不要当作已经发生。
- 诉讼请求、一方的主张（「被告应承担连带责任」）放进 `claims`，不是事实。
- 约定类事实（`state: "agr"`）除了挂约定条款，还要挂一条协议签订日的记载，否则它会落进「无日期」。

### 同一笔钱的几个环节，各成一件事

一笔款常有「确认票面 → 开票 → 到账」几个环节，日期、金额都不同（差额常是贴息、手续费）。**每个环节各建一个事实**；不同口径的金额绝不放进同一个事实的 `amt`，口径差异写进 `cnote`。判决书对这笔款只用一个口径时，引用判决那条记载 `amt` 留空。

同一个金额在不同材料里性质不同（如一处记「结算款」、一处记「保理贴息」）：各条记载写上 `nature`，检查脚本会提醒。

## 二、标题怎么写

- 15 字左右，主语＋动作＋对象：「李四出具借条」「张三短信催告限期还款」「监理签发开工令」。
- 只写发生了什么，不写评价、不写法律定性：不写「违约」「恶意拖欠」「拒不还款」「依法」。
- 需要引原话时用「」，如：李四称「这个月先还5万」。「」里的字必须能在出处原文里找到。
- 不同方说法不同的，标题写各方都认可的部分（「出借人交付借款」），分歧留给记载。

## 三、记载怎么挂

每条记载回答：**哪份材料、哪个位置、原话是什么、日期原文怎么写、折成哪天、金额多少。**

- 引语 `q`：从 `lines` 里复制，一字不改，包括标点和空格。检查脚本按字比对。
- 日期原文 `raw`：原文怎么写就怎么写（「2023年3月1日」「2023-03-03」「3/3 16:20」「下周一」「腊月二十前」）。`raw` 必须出现在 `q` 或 `qx` 里，读者才看得到日期从哪来。
- 一条记载只记一个日期（或一个区间）。同一份材料对同一件事前后写了两个日期，挂两条记载。
- **裁判文书、函件、笔录的作出时间挂在落款（或首部）那一条记载上**，`raw` 用落款写法（如「二〇二四年六月二十四日」）；「本院认为」「经审理查明」等段落本身不带日期（`p: none`）。「判决作出」「裁定作出」这类事实用落款那一条记载。
- **`loc` 要写清出自文书哪个部位。** 判决书、答辩状、笔录里的「诉称」「辩称」「质证」「拟证明」段落是当事人的说法，`loc` 里要带这些词（如「第2页 原告诉称」「证据3 拟证明」），或在记载上写 `stmt: true`；否则会被当成书证，页面不会提示「仅有当事人陈述」。确是法院认定的，`loc` 写「本院查明」「本院认定」。

### 日期精度 `p`

| 原文 | p | s / e |
|---|---|---|
| 2023年3月1日 | `day` | `2023-03-01` |
| 2024年1月 | `month` | `2024-01` |
| 2024年6月3日至7月14日 | `range` | `2024-06-03` / `2024-07-14` |
| 约在9月底、月底前后 | `approx` | 取最可能的一天 |
| 春节前后、上半年 | `arange` | 起止取合理范围 |
| 没写时间 | `none` | 不填 |

### 推断日期

原文的日期需要推算才能落到公历时，照下面做，并在 `inferences` 里写依据：

| 情形 | 类别名（`n`） | 依据要写什么 |
|---|---|---|
| 缺年份（聊天记录「3/3」） | 原文未载年份 | 凭什么定是哪一年（相邻消息、回单日期等） |
| 相对日期（「下周一」「三天后」） | 原文为相对日期 | 以哪天为基准，怎么算 |
| 农历（「腊月二十」） | 原文为农历日期 | 对应的公历 |
| 按天数推算（「42 天后」） | 依原文天数推算 | 起算日与天数 |

推不出来的，`p` 写 `none`，不要猜。

### 可疑日期

原文日期本身不成立（「2月30日」「6月31日」），或与同一份材料的其他记载明显矛盾（如同一份竣工报告里监理签字写成前一年）：照录 `raw`，`s` 填最接近的有效日期，标 `sus: 1`，`susWhy` 写原因。页面默认不按它上时间线，交律师确认。

### 金额

- `amt` 填数字，单位统一（底稿 `unit`）。同一件事各份材料金额不同的，照实各填，页面会列为「金额冲突」。
- 大写与小写金额不一致的，照录，不纠正；页面会自动查出来。

## 四、证据种类与程序状态

- 书证 `record`：合同、借条、收据、回单、函件、签证单、鉴定意见等。
- 电子数据 `edata`：聊天记录、短信、邮件、电子转账记录截图等。
- 当事人陈述 `statement`：起诉状、答辩状、代理词、情况说明、当事人笔录。
- 证人证言 `testimony`：证人证言、证人出庭笔录。
- `confirm` 程序状态按用户告知填写；不知道的写「已提交」或不填。

## 五、线索（threads）

- 按「事情的线索」分组，不按材料、不按时间段。民间借贷常见：借款的成立与交付／还款／催收与诉讼／担保。建设工程常见：合同签订／开工／停工与复工／签证与变更／竣工验收／结算与付款／诉讼。
- 每个事实只进一个线索；线索内按时间排。

## 六、关联（relations）

只连材料**写明**的指向：回单备注「还借款」、函件写「根据贵司某月某日来函」、开工令写「依据合同第7条」。不由你推断「因为 A 所以 B」。

## 七、各领域包的事实角色（`role`）

| 包 | 角色 | 专属检查 |
|---|---|---|
| lending 民间借贷 | 借款合意、借款交付、还款、催收、担保、利息约定 | 借款交付、还款要有带「转账凭证」标签的材料 |
| construction 建设工程 | 开工、停工、复工、竣工验收、付款、结算、签证 | — |
| sale 买卖合同 | 订货、送货、验收、对账、开票、付款、催款 | 各送货金额之和应与对账一致 |
| lease 房屋租赁 | 签约、押金收取、租金支付、交还房屋、押金退还 | 押金要有「收据」，租金要有「转账凭证」 |
| tort 交通事故 | 事故、责任认定、住院、医疗费票据、医疗费合计、误工、垫付 | 各票据之和应与合计一致 |
| family 婚姻家事 | 结婚、购房、出资、分居 | 出资要有「转账凭证」 |
| labor 劳动争议 | 入职、签订合同、工资发放、解除、仲裁 | — |

用到专属检查时，记得给对应材料加 `tags`（转账回单加 `["转账凭证"]`）。
