# ADR 0006 — 首轮事实复核与待审

**状态：** 拟提交

## 使用场景

接到大量材料时，律师先看 Agent 预处理的案情，再沿事实表逐条核对。熟悉案情后，律师也可以直接到顶部「待审」，集中处理材料分歧。

## 决策

- 纳入标准是与诉辩和证据的关联性。重要程度由关键标记表达。Agent 首轮提取后按诉请和抗辩回查材料，普通条目也可点回出处。
- 事实详情可按当前表格顺序切换。绿色表示现有记载未见冲突。待核事项和明确冲突各有颜色和文字提示。
- 待审卡依次列证据名称和页码、发现差异的依据及原始记载。采用按钮显示具体日期或金额。律师也可确认已经复核，同时保留各方记载。
- 同一事实的日期、金额和关联提醒计为一项。确认或撤销时，同步更新事实状态与顶部待审数。卷册级的独立待审单列。
- 一键确认前可展开范围，逐条看日期、事实与摘要。按钮仅处理本阶段尚未确认、未见冲突且没有待核事项的事实。

- 横向时间线的右侧增加纵向疏密滑条，支持「汇总」「展开重叠」「逐条」。日期刻度、横向缩放和泳道保留。逐条展示时显示每条事实的日期、标题和材料编号，材料目录可在图下展开。按月浏览仍可从「纵向」进入。
- 汇总徽标和旁边的数量文字同为展开入口。旧版点击只缩小横轴日期范围，同一天的事件仍然重叠。现在直接在原泳道纵向展开一组，并可收起恢复。
- 当手写、盖章或扫描质量影响字段识读时，把有疑点的原始页影像附在待审卡。以页码和理由定位，律师能在同一张卡对照摘录与原页。
- 律师可以填写不同于现有选项的解释或补核意见。意见随底稿导出，等待 Agent 结合证据处理。页面内的采用和确认即时反映在待审与时间线上。

## 取舍

按时间复核和集中待审使用同一份事实及审阅状态。集中待审优先展示材料名称和差异依据，律师可据此决定是否展开原文。只给不同日期或只给相差天数，无法说明两份材料写的是不是同一个字段。Agent 可用 cnote 描述原始字段，缺少说明时页面用已有日期和金额生成摘要。点击确认或采用会更新审阅状态，仍待 AI 处理的律师意见继续显示在待审里。

## 复现

1. 用 python3 web/build.py --demo 生成示例页面，打开虚构的民间借贷案。
2. 从事实表第一条向后切换。检查普通事实和「出借人交付借款」的提示。借条和转账回单分别记载 2023 年 3 月 1 日、50 万元与 2023 年 3 月 3 日、48 万元。
3. 从顶部「待审」打开这一项。核对证据名称、差异依据及原始记载。点「已确认，保留不同记载」，总数应减一。撤销后总数应恢复。也可采用一份具体记载，核对总数同样减一。
4. 展开「查看本次确认范围」，核对清单后点一键确认。清单中的事实变为已确认，其他待审仍可逐条查看。导出底稿可保存审阅结果。

5. 切到「纵向」，收起全部后展开一个月，核对每条事实均有独立行。采用不同日期后，事实按采用日排，详情仍保留其他日期。
6. 给模拟证据添加签署页影像和复核理由。打开待审卡放大检查原页，填写其他复核意见。导出并重新打开底稿，检查意见与影像都可读，且待处理的意见仍在待审。

7. 用含有同一天多条记录的示例底稿，从汇总视图点击圆圈或旁边的件数。检查组内事实分别占行，横轴范围保持，点标题可打开详情。拉动右侧滑条，在「逐条」检查所有带日期的事实标题与来源、无日期事实以及材料目录。

用 python3 tests/run_checks.py 检查底稿和模板。
